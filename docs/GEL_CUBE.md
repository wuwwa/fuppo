# Gel Cube

Open `?toy=gel-cube` or choose Gel Cube in the collection. The original Butter home page stays unchanged, and Dough remains parked.

The cube is a rounded block of cool teal gel. A quick poke gives a shallow response; a longer press yields progressively and bulges the sides. A short press recovers sooner than a sustained squeeze. Pulling quickly gives immediate, resisted elastic travel; slow movement or holding the pull lets the same patch extend farther. Releasing at any point returns it to its original cube. There is no burst, score, success condition, or delayed bonus required for the basic response.

## Model

`gelCubeProfile` opts into `feel.viscoelastic`. Each grip keeps a delayed stretch target alongside its immediate elastic response. History is updated on physics ticks rather than pointer-event counts. Equal-length fast and slow pulls therefore take different paths toward the same bounded equilibrium.

Compression uses two parallel responses: immediate elastic deformation and a slower load-dependent component. The slow component drains on release, so a brief poke stores little delayed deformation while a long squeeze recovers gradually. Only vertically loaded contacts maintain this component; a remaining side grip does not hold another finger's squeeze in place. Local dents use loaded hold duration, not time spent pulling with pressure relieved. This is a qualitative digital material model, not calibration to a physical product.

Unlike Butter's foam, the cube keeps the gel volume constraints and sideways expansion. A rounded box mesh with broad faces displays the deformation. The lower-resolution shared cage remains a limit on very fine fingertip impressions. Extreme pulls stay bounded and the original shape is recovered exactly by Reset.

Touch, keyboard, rotation, pair turning, sound consent, volume, hidden-page/collection pause, reduced motion and disposal use the existing shared player. Sound reuses the local gel recordings at a lower pitch; [the original provenance](ASMR_AUDIO.md) remains in place. No new audio downloads or runtime services are required.

## Verification

`tests/gel-cube.test.ts` checks visible early response versus held depth, differing short/long recovery, equal-distance fast/slow pulls and held convergence, partial release, closed geometry, visible volume under compression/recovery, finite extreme five-finger input, reduced motion and exact reset. The full existing test suite remains the regression check for other materials.

With the development server running, the shared Chrome harness accepts `--gel-cube`:

```sh
npm test
npm run build
QA_ORIGIN=http://127.0.0.1:5177 CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node qa/turn-smoke.mjs --gel-cube
QA_ORIGIN=http://127.0.0.1:5177 CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' node qa/turn-smoke.mjs --gel-cube --webgl
```

The browser checks cover native dispatched touch, two-finger stretch and partial release, orientation cancellation, keyboard with reduced motion, mouse input, sound opt-in/mute, recovery to idle, compact layout, collection registration, and stable graphics resources. Captures and results are written to ignored `qa/artifacts/`. The collection thumbnail is a real render generated by `qa/capture-previews.mjs --toy=gel-cube`.

These automated checks establish behavior and bounds, not subjective tactile satisfaction, physical-phone frame rate, thermals or battery use. Compare short pokes, slow holds, interrupted holds and slow/quick pulls on a physical phone before calling the feel final.
